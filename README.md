# te-tengo-infra

Infrastructure for **Te Tengo**: create the VM, configure the server and deploy the backend. Production must cost as little as possible, and the whole cloud side is **Microsoft Azure** on the **Azure for Students** subscription (US$ 100 credit): one VM (`Standard_B2ats_v2`, 2 vCPU / 1 GiB, in `chilecentral`; the size is in the offer's 750 free hours a month, the static IP and the disk are paid from the credit) and **Azure Blob Storage** for clips, movement files, photos, database dumps and the Terraform state, reached with the VM's **managed identity** (no storage keys anywhere); ≈ US$ 7.3/month plus disk operations, and blob egress is not free beyond the subscription's 100 GB a month ([docs/terraform.md](docs/terraform.md#cost-what-the-credit-pays)). DNS records are created by hand at the registrar (**Namify**), the landing page is on Cloudflare Pages, push goes through Firebase Cloud Messaging and e-mail through a generic SMTP relay. The only Cloudflare R2 bucket left is the public downloads bucket of the app releases (`TT_VERSIONES_URL_BASE`), owned by the release workflows of the app repositories. Moving production from R2: [docs/deploy.md](docs/deploy.md#migrate-from-cloudflare-r2-to-azure-blob).

| Folder | Tool | Contains |
|---|---|---|
| `envs/azure/`, `modules/te-tengo-azure/` | Terraform | **Active.** One `Standard_B2ats_v2` VM (Ubuntu 24.04 x64, 30 GB Standard SSD, Trusted Launch, system-assigned managed identity) with a static Standard public IP in a minimal virtual network; NSG open on 80, 443 (TCP+UDP), 8322 and 8189 (TCP+UDP, WebRTC live view), SSH (key only) from `admin_cidrs`; a storage account (Standard_LRS, shared keys off, private containers `clips`, `movements`, `backups`, lifecycle policy, CORS for the PWA) with the VM's roles on it; state in Azure Blob (`backend "azurerm"`, Entra ID); renders the Ansible inventory; tested offline with a mocked provider ([docs/terraform.md](docs/terraform.md)) |
| `bootstrap-azure/` | Terraform | One-time root (local state) that creates the Terraform state storage account and its `tfstate` container ([docs/terraform.md](docs/terraform.md#remote-state-on-azure)) |
| `envs/oci/`, `modules/te-tengo-oci/` | Terraform | **Inactive OCI alternative** (no Ampere A1 capacity was available): one `VM.Standard.A1.Flex` on Always Free; validated and tested offline, never applied |
| `envs/mvp/`, `modules/te-tengo/`, `bootstrap/` | Terraform | **Inactive AWS alternative**, never applied: the same host on EC2 `t4g.small`, "VM only" by default (S3, SES, SNS and Route53 optional); verified against the Floci emulator through `envs/local/` |
| `ansible/` | Ansible | Configure the host over SSH (Azure, OCI) or SSH over SSM (AWS): updates, swap, zswap, unused host services masked (Azure, OCI), the OCI image firewall (OCI only), Docker; deploy `compose/` with the memory profile of the VM (`tiny` for 1 GiB); API settings for Azure Blob Storage (`object_storage_provider: azure`, managed identity); daily PostgreSQL backups to the `backups` container with azcopy ([docs/ansible.md](docs/ansible.md)) |
| `compose/` | Docker Compose | Caddy (TLS), `te-tengo-general-api`, PostgreSQL 18 and MediaMTX (live view). With video processed on the household PC (ADR 0007 in the desktop agent repository), there is **no detection container** |
| `test/` | Docker | Local stand-in for the VM (Ubuntu 24.04 + systemd + SSH, capped at 1 GiB like the Azure VM) and Azurite as the storage account: `make test-all` deploys, smoke-tests and measures the stack without any cloud account |

**Deploying:** [docs/deploy.md](docs/deploy.md) (runbook, secrets, rollback). **Release flow** (git flow with release candidates, "build once, deploy many", tag at the end; [docs/deploy.md](docs/deploy.md#4-release-flow-and-continuous-deployment-github-actions), with a diagram): a push to `release/x.y.z` or `hotfix/x.y.z` verifies the release commit automatically on the containerized test host (`make test-all`, with the API image in production; there is no staging target), records it as the pre-release `vX.Y.Z-rc.N` with its git tree hash and opens the pull request to `main`. The pull request (opened by the GitHub App te-tengo-release-bot) can only be merged once `release-gate` sees that verified candidate. After the merge, `main` deploys **that** configuration with every role (its tree hash must match the candidate's) and only then tags `vX.Y.Z` (version in [`VERSION`](VERSION), notes from [`CHANGELOG.md`](CHANGELOG.md)). An API release reaches the VM the same way, from te-tengo-general-api's `main`: it sends `repository_dispatch` `desplegar-api` here with the image digest and waits for the result. Both go through the **Deploy** workflow, which waits for approval on the GitHub environment **`produccion`**, then for any other running deploy, runs the Ansible playbook over SSH (the app role for an API image, every role for an infra release) with the committed, non-secret production settings of [`ansible/prod.yml`](ansible/prod.yml), pins the API image by digest, **backs up the database before the image changes** and checks `/actuator/health` and that the running API container is the requested digest. A **Rollback** workflow puts an earlier configuration back. Switch (organization variable, `true` = on): `ENABLE_API_DEPLOY`, which freezes production ([docs/deploy.md](docs/deploy.md#switches)). **Contract between Terraform and Ansible:** [docs/interface-terraform-ansible.md](docs/interface-terraform-ansible.md).

**Reference:** the physical architecture lives in `04-arquitectura/` of `Te-Tengo-Tech/docs` (Spanish). It must be updated for processing on the household PC and for Azure (VM and Blob Storage).

**Never commit credentials or state files** (`*.tfstate`, `.terraform/`, `*.tfvars`, `backend.hcl`, `~/.azure`, `~/.oci/config`, the Ansible vault unencrypted); see `.gitignore`. Applies are run by an operator: CI never plans or applies against a real cloud; it only deploys the app role, after approval.
